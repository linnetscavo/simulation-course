# Лабораторная работа 9
## Дискретно-событийное моделирование системы массового обслуживания (СМО)

### 1. Цель работы
Разработать программную модель системы массового обслуживания (СМО) с неограниченной очередью и $N$ параллельными приборами (операторами). Реализовать дискретно-событийный алгоритм моделирования, позволяющий использовать произвольные законы распределения времени прибытия и обслуживания. Выполнить сбор статистики по времени ожидания и длине очереди, визуализировать эмпирические распределения.

### 2. Математическая модель

#### 1. Описание системы
Моделируемая система представляет собой СМО типа $M/M/N$, состоящую из:
*   **Входящего потока заявок** с интенсивностью $\lambda$. Интервалы между поступлениями — независимые случайные величины.
*   **Очереди** неограниченной емкости, дисциплина обслуживания — FIFO (First In, First Out).
*   **$N$ обслуживающих приборов**, каждый со своей интенсивностью обслуживания $\mu$. Время обслуживания одного клиента — случайная величина.

Состояние системы в момент времени $t$ описывается двумя переменными:
*   $x(t)$ — количество занятых приборов ($0 \le x \le N$).
*   $y(t)$ — количество заявок в очереди ($y \ge 0$).
*   Полное число заявок в системе: $L(t) = x(t) + y(t)$.

#### 2. Алгоритм моделирования (Дискретно-событийный подход)
В отличие от пошагового моделирования, время в модели скачкообразно перемещается к моментам наступления ближайших событий. Используется **календарь событий**, хранящий абсолютные моменты времени:
*   $t_a$ — момент следующего прибытия заявки.
*   $t_s[i]$ — момент окончания обслуживания на $i$-м приборе ($\infty$, если прибор свободен).

**Логика шага симуляции:**
1.  Определить ближайшее событие: $t_{next} = \min(t_a, t_s[1], \dots, t_s[N])$.
2.  Переместить модельное время: $t = t_{next}$.
3.  Обработать событие:
    *   **Прибытие ($t == t_a$):**
        *   Если есть свободный прибор ($x < N$): занять его, сгенерировать время окончания обслуживания $t_s[i] = t + \tau_{serv}$, увеличить $x$.
        *   Иначе: добавить заявку в очередь ($y++$).
        *   Запланировать следующее прибытие: $t_a = t + \tau_{arr}$.
    *   **Окончание обслуживания ($t == t_s[k]$):**
        *   Освободить прибор $k$ ($t_s[k] = \infty$, $x--$).
        *   Если очередь не пуста ($y > 0$): взять заявку из очереди, занять прибор $k$, сгенерировать новое $t_s[k] = t + \tau_{serv}$, уменьшить $y$.
4.  Повторять, пока $t < T_{model}$.

> **Примечание:** Данный алгоритм универсален и позволяет использовать любые распределения (экспоненциальное, нормальное, равномерное) для $\tau_{arr}$ и $\tau_{serv}$, в отличие от аналитических методов, работающих только для экспоненциального случая.

#### 3. Сбор статистики
Для каждой обслуженной заявки фиксируются:
*   $t_{arr}$ — время прибытия.
*   $t_{start}$ — время начала обслуживания.
*   $t_{end}$ — время окончания обслуживания.

Вычисляемые метрики:
*   Время ожидания в очереди: $W_q = t_{start} - t_{arr}$.
*   Время пребывания в системе: $W_s = t_{end} - t_{arr}$.
*   Мгновенная длина системы $L(t)$ фиксируется в моменты всех событий для построения полигона частот.

### 3. Ключевые методы реализации

**Генерация случайных интервалов (`get_random_interval`)**
Функция поддерживает три типа распределений:
1.  **Exp (Экспоненциальное):** $\tau = -\ln(U) / \lambda$. Использует свойство отсутствия последействия.
2.  **Norm (Нормальное):** $\tau \sim N(\mu_{loc}, \sigma^2)$. Параметры подбираются так, чтобы математическое ожидание совпадало с $1/\lambda$ или $1/\mu$.
3.  **Unif (Равномерное):** $\tau \sim U(a, b)$. Границы выбираются так, чтобы среднее значение соответствовало обратной интенсивности.

**Ядро симуляции (`run_simulation_core`)**
Реализует универсальный алгоритм с календарем событий:
1.  Инициализирует массив времен окончания обслуживания `ts` значениями $\infty$.
2.  В цикле `while t < T_MODEL` определяет тип ближайшего события путем сравнения `ta` и `min(ts)`.
3.  При обработке события обновления состояния системы (`n_busy`, `queue`) и генерирует новые времена будущих событий.
4.  Накопляет статистику по времени ожидания (`stats_w_queue`) и длине системы (`stats_L_samples`).

**Визуализация (`plot_results`)**
Использует `matplotlib` для построения двух графиков:
1.  **Полигон частот распределения $L$:** Показывает вероятность нахождения в системе $k$ заявок. Позволяет оценить загрузку системы.
2.  **Гистограмма времени ожидания $W_q$:** Отображает плотность распределения времени ожидания. Красной линией отмечено среднее значение.

### 5. Выводы по графикам экспериментов:
- При увеличении λ (при фиксированном N) пик на графике L сдвигается вправо, а хвост гистограммы Wq становится длиннее — клиентов больше, ждут дольше.
- При уменьшении N (при фиксированном λ) графики становятся «шумными» и растянутыми — очередь растет хаотично, время ожидания разбросано от 0 до очень больших значений.
- При увеличении N (при фиксированном λ) пик L смещается влево (ближе к нулю), а гистограмма Wq сжимается у нуля — почти все клиенты обслуживаются сразу.
- На всех графиках Wq при экспоненциальном распределении есть длинный правый хвост — всегда есть небольшая доля клиентов, которые ждут аномально долго.
- Когда система перегружена (например, λ=9, N=10 или λ=2, N=1), график L теряет четкий пик и становится «размазанным», а Wq показывает экстремальные значения (до 75–200 единиц времени).

### Ключевой вывод по типам распределений:
Чем меньше случайность (дисперсия) во времени прибытия и обслуживания — тем лучше работает система.

- exp/exp → худший случай: максимальная случайность → длинные очереди, большие ожидания.
- unif/exp или exp/norm → лучше: один процесс предсказуемее → снижает риск заторов.
- unif/norm → лучший случай: оба процесса предсказуемы → минимальные очереди и время ожидания.
Это подтверждает теорию: дисперсия входных потоков напрямую влияет на производительность СМО.
